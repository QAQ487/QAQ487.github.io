# UI-04 · Error shake / Invalid-input shake

**Aliases:** Shake on error; Wrong-password shake; Head-shake feedback; Rejection wiggle

**Group:** UI & HUD
**Subcategory:** UI motion

## What you see

When an input or action is refused (wrong password, not enough money, inventory full / pickup blocked), that field, button or hotbar slot quickly shakes left-right 3–4 times in place and settles, like a head shaking "no", usually turning red with a short explanation (e.g. "Inventory full").

## Not to be confused with

Not screen shake (FB-07, the whole camera moves); an error shake moves only the rejected UI element. Not easing (UI-01, moving from A to B).

## Use it for

Password/code entry, cannot afford, slot full, pressing a skill on cooldown. Says "no" immediately without a pop-up.

## Tunable parameters

amplitude (px) · swing count · duration · decay curve · colour flash · reduced-motion fallback

## Request prompt

On rejected actions keep focus and show the reason at the control (e.g. "Inventory full" beside the hotbar slot); optional error shake reinforces it. For unaffordable buys, shake the price 6 px over 0.35 s for 3 swings and tint red; under reduced motion flash a red outline only.

## Implementation hint

offsetX = A * sin(k * 2π * n) * (1 - k)^2 with k = elapsed / duration, applied as a UI-local translation (never move the camera). Restart cleanly if triggered again mid-shake. Always pair with text or colour so the meaning does not rely on motion alone.
