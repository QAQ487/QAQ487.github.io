# UX-34 · Lock-and-key gate / Ability gating

**Group:** Visual guidance & wayfinding
**Subcategory:** Access Rules, Returning, and Learning

## What you see

You first see a locked door, then find its key; alternatively, a cracked wall in an old area becomes breakable after you learn a wall-breaking ability. In the latter case, the ability acts as an abstract key.

## Not to be confused with

The key need not be a literal metal key; buttons or quest states can be keys too. An ability gate is not necessarily a skill test: the former may mean the ability is not unlocked, while the latter means you have it but have not learned to use it.

## Use it for

You first see a locked door, then find its key; alternatively, a cracked wall in an old area becomes breakable after you learn a wall-breaking ability. In the latter case, the ability acts as an abstract key.

## Tunable parameters

locked obstacle · key state · ability prerequisite · foreshadowing · return route · unlock feedback

## Request prompt

Place 2 cracked walls in area 1 that report Impact ability required; after unlocking the ability in area 3, mark the old obstacles on the map and allow return to break them, without adding a separate skill test or treating the locked ability as player error.

## Implementation hint

Store the obstacle’s prerequisite as an explicit item, quest, or ability state and provide feedback both before and after acquisition. Preserve enough context or mapping for players to revisit earlier gates without confusing an unavailable ability with failure to perform it.
