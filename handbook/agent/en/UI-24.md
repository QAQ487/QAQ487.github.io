# UI-24 · Contextual HUD / dynamic HUD

**Aliases:** 情境 HUD; 平時冇血條受傷先出; 有任務先彈任務資訊; Dynamic HUD; Context HUD; Auto-hide HUD; 状況HUD; ダイナミックHUD

**Group:** UI & HUD
**Subcategory:** HUD & interface types

## What you see

Health, resources and tracked objectives each have show rules: appear on change, hide after idle, stay visible while critical, and offer an always-on option. When they return they reuse the same anchors. Can split reticle-local vs edge information.

## Not to be confused with

Not “no HUD” as a pure aesthetic, and not a permanently pinned HUD (UX-01’s default). This entry is the show/hide policy.

## Use it for

Immersive action and shooters, exploration titles that fear clutter.

## Tunable parameters

show triggers · hide delay · critical always-on · per-widget anchors · always-on setting · reticle vs edge layers · fade time

## Request prompt

List show conditions for health, resources and tracked objectives. Reveal the health bar on change and hide it after the value is stable. Keep it visible while critical and offer an always-on option. Reuse original anchors whenever elements return.

## Implementation hint

Each widget has {anchor, visibleUntil, forceOn}. On value delta set visibleUntil = now+delay; if value < criticalKeep, latch visible. Settings can force all on. Do not reflow anchors when toggling—only alpha/scale—so players keep spatial memory (pair with UX-01).
