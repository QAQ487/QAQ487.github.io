# FB-07 · Trauma-based screen shake

**Aliases:** Trauma shake; Perlin screen shake; Camera shake

**Group:** Combat feedback & game feel
**Subcategory:** Camera feedback

## What you see

Shake is driven by a "trauma" value (0–1) instead of a fixed wobble: each hit adds trauma, trauma decays over time, actual amplitude = trauma², and offset/rotation come from smooth noise.

## Not to be confused with

Not per-frame random jitter (which looks cheap) nor camera kick (FB-08, one directional jolt). Trauma shake stacks and settles naturally.

## Use it for

Explosions, heavy hits, boss landings; many simultaneous events add up without going out of control.

## Tunable parameters

trauma add per event · decay/s · exponent (2–3) · max offset & angle · noise frequency · pixel rounding

## Request prompt

Add trauma-based shake to the game camera: trauma 0–1 decaying 1.5/s; amplitude = trauma²; max offset 6 px and max rotation 2°, sampled from Perlin noise at ~15 Hz. Normal hit +0.2, explosion +0.6. In pixel mode round the final offset to whole pixels.

## Implementation hint

Camera-only: offset = maxOffset * trauma^2 * noise(seed, t*freq) per axis; angle likewise. Apply in the view matrix before the pixel-snapped blit (or round offset when rendering at native low res). Never move the world objects themselves.
