# UI-03 · Button feedback (hover, press, disabled)

**Aliases:** Button states; Interaction states; Hover / pressed / disabled; Press feedback; Focus selected pressed disabled; 裝備格狀態對照

**Group:** UI & HUD
**Subcategory:** UI motion

## What you see

A button looks clearly different in each state: it brightens, lifts or gains an outline when the cursor or focus is on it (hover/focus); it sinks, darkens and loses its shadow when held (pressed); it springs back slightly on release; when unavailable it is grey, low-contrast and does nothing when clicked (disabled).

## Not to be confused with

Not the focus highlight design on its own (which only shows which item is selected); button feedback is one button changing between states. Not an error shake (UI-04, which says "this action was rejected").

## Use it for

Anything clickable or confirmable: main menus, shops, dialogue choices. The player should know "this can be pressed" before pressing and "that registered" the instant they do.

## Tunable parameters

state colours · hover offset (px) · press depth (px) · transition times per state · release overshoot · disabled opacity · focus outline width

## Request prompt

On one equipment slot show focus (white ring), equipped (corner check), pressed (brief squash) and disabled (lock + reason). Keep the same four states on ordinary buttons. Restore prior focus after a modal; if that item was removed, select the nearest enabled slot.

## Implementation hint

Model the button as a tiny state machine (normal/hover/pressed/disabled, plus focused for gamepad). Draw from a 9-slice (UI-14) with a per-state tint and y-offset rather than separate textures where possible. Pressed must show on the press event, not on release, or the UI feels laggy.
