# UX-38 · Checkpoint / Respawn point；Autosave

**Group:** Visual guidance & wayfinding
**Subcategory:** Access Rules, Returning, and Learning

## What you see

After touching a flag, entering a room, or completing an encounter, failure returns you to a specified state/location. Spacing directly affects how much you repeat on a retry. Autosave means automatically writing a save; respawn point emphasizes the location where you reappear.

## Not to be confused with

A checkpoint does not guarantee persistent saving after quitting; a respawn point does not guarantee retained item/enemy states; an autosave may preserve a dangerous situation. Distinguish recovery after death, loading a save, and quitting then restarting.

## Use it for

After touching a flag, entering a room, or completing an encounter, failure returns you to a specified state/location. Spacing directly affects how much you repeat on a retry. Autosave means automatically writing a save; respawn point emphasizes the location where you reappear.

## Tunable parameters

checkpoint trigger · respawn location · restored state · autosave · retry distance · quit behavior

## Request prompt

Configure 3 checkpoints with under 45 seconds of replay between them; on death respawn at the latest flag, retain collected items, and reset enemies. Autosave only after encounters, never mid-combat, and test death, load, and quit-restart as 3 distinct recovery paths.

## Implementation hint

Define checkpoint activation, respawn position, restored world and inventory state, and persistent save writes as separate rules. Test death, manual load, and quit-restart independently, including unsafe autosave prevention and retry distance.
