# UX-22 · Signifier / Interaction cue

**Aliases:** Affordance; 可供性; Signifier matches action; 旗點亮起; Checkpoint flag

**Group:** Visual guidance & wayfinding
**Subcategory:** Spatial Recognition and Guidance

## What you see

A handle’s shape, markings on a climbable ledge, button text, or an interaction outline suggests a possible action or state.

## Not to be confused with

Signifiers are not limited to deliberately drawn icons; players may also interpret environmental traces as clues. Giving something a conspicuous appearance without any function creates false expectations.

## Use it for

A handle’s shape, markings on a climbable ledge, button text, or an interaction outline suggests a possible action or state. An interaction cue must match what can actually be done: a wall that cannot be climbed must not use the same prominent mark as a climbable one. When a checkpoint flag is reached, the flag itself lighting or changing colour is a state cue, not the retry rule. (Former entry UX-21, “Affordance”, is merged here; the flag lighting comes from former entry UX-38.)

## Tunable parameters

interaction outline · handle shape · action label · consistency · false cue · state cue

## Request prompt

Design 3 signifiers for a usable lever: a clear handle shape, a 2 px outline, and the label Pull; show the outline within 3 m, replace it with a lock symbol when disabled, and do not give 5 decorative levers the same conspicuous treatment.

## Implementation hint

Use consistent visual, textual, or environmental cues to signal actual available actions and states. Generate cues from interaction eligibility where possible so decorative objects do not accidentally promise unavailable behavior.
