# UX-31 · Critical path / Main path；Optional path / Side path

**Group:** Visual guidance & wayfinding
**Subcategory:** Access Rules, Returning, and Learning

## What you see

One sequence of spaces/events advances required objectives, while another branch holds supplies, secrets, or extra story. Recognizing the distinction lets you choose whether to explore or advance first.

## Not to be confused with

The critical path is not necessarily the geometrically shortest route or the only reasonable way to play. This concerns level progression, not the critical path method in project management.

## Use it for

One sequence of spaces/events advances required objectives, while another branch holds supplies, secrets, or extra story. Recognizing the distinction lets you choose whether to explore or advance first.

## Tunable parameters

required objective · main route · optional branch · reward · rejoin point · player choice

## Request prompt

Design 1 main progression route containing 2 required switches and 2 optional branches with supplies or story; rejoin each branch after 30–45 m, let players explore first, and do not require the main path to be geometrically shortest.

## Implementation hint

Model required progression separately from optional branches and communicate their consequences without forbidding exploration. Let side paths rejoin cleanly and avoid equating the critical path with either the shortest geometry or the only valid play style.
