# A11Y-03 · Colour-blind modes with shape redundancy

**Aliases:** 色盲模式; 紅綠分不清; 敵我顏色難分; Colour-blind mode; Daltonization; Shape redundancy; Colour vision deficiency; 色覚サポート

**Group:** Readability & accessibility
**Subcategory:** Visual modes & comfort

## What you see

Information the game separates by colour — friend or foe, rarity, danger zones, teams — is also expressed by shape, pattern or icon; a colour-blind mode additionally swaps easily confused colour pairs (such as red and green) for distinguishable ones, or applies a whole-screen correction (Daltonization). The point is that it still works with colour removed; the colour-blind mode is only reinforcement.

## Not to be confused with

Not multimodal redundant cues (UX-18, sound, vibration and visuals backing each other up) and not text contrast (A11Y-01). This entry is only about colour never being the sole carrier of information.

## Use it for

Team and friend-or-foe markers, item rarity, danger zones on maps, puzzle and matching games, chart and minimap legends.

## Tunable parameters

presets protan / deutan / tritan · custom palette · shape set ≥3 · simulation matrices (Machado 2009) · per-element override (starting points)

## Request prompt

Add colour accessibility: give every colour-coded marker a shape (circle, triangle, square) or pattern as well; offer presets for red–green (protan, deutan) and blue–yellow (tritan) colour vision deficiency plus a custom palette. Check every UI screen through a colour-vision-deficiency simulation filter and archive the screenshots.

## Implementation hint

Author semantic colour tokens (ally, enemy, rare…) and map them through a preset table, rather than recolouring the final frame. Optional full-screen Daltonize: simulate CVD with a 3×3 matrix, compute error = original - simulated, redistribute error into visible channels. Debug view: apply simulation matrix to the whole frame.
