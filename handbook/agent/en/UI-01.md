# UI-01 · Tweening / Easing curves

**Aliases:** Easing; Ease in / ease out; Interpolation curve; Tween

**Group:** UI & HUD
**Subcategory:** UI motion

## What you see

When a UI element goes from A to B (position, scale, opacity) it does not move at constant speed: it starts slow, ends slow, or overshoots and settles back. Look at the spacing along the path: linear spacing is even, ease-out has wide gaps at first and bunches up near the end.

## Not to be confused with

Not an error shake (UI-04, an in-place decaying oscillation); easing is the speed profile of going from one place to another and underlies all UI motion. Not frame-by-frame sprite animation.

## Use it for

Every interpolation: sliding panels, bouncy buttons, number rolls, camera moves. Makes the interface feel weighty and responsive instead of teleporting or moving mechanically.

## Tunable parameters

duration · curve family (sine/cubic/quint/back/elastic/bounce) · in / out / in-out · overshoot amount · delay & stagger between items

## Request prompt

Standardise UI easing in your game: all entrances use ease-out cubic over 0.25 s; exits use ease-in cubic over 0.18 s; buttons and rewards that should feel springy use ease-out back (overshoot 1.7); never move UI linearly (progress bars excepted). Put the curves in one shared helper so every tween only takes start, end, duration and curve name.

## Implementation hint

A tween is value = lerp(a, b, ease(clamp((now - start) / duration))). Keep tweens in a small manager updated once per frame with unscaled UI time (so pause/slow-motion does not freeze menus). Use standard Penner-style formulas; ease-out-back: 1 + c3*(x-1)^3 + c1*(x-1)^2 with c1 = 1.70158, c3 = c1 + 1.
