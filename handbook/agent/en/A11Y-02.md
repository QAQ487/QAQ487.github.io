# A11Y-02 · Text scaling and reflow

**Aliases:** 字太細; 放大字體後文字被裁掉; 字幕放大後超出框; Text size option; Resize text; UI text overflow; Truncated text; Font scaling; テキストのサイズ変更; リフロー

**Group:** Readability & accessibility
**Subcategory:** Text legibility

## What you see

When the player turns up text size in settings, dialogue boxes, prompts and menus automatically grow taller or re-wrap so everything stays complete and readable. Done badly, text is clipped, spills outside its box, overlaps icons, or there is no text-size option at all. A legibility baseline is a minimum font size at 1080p of about 26 px on console and 18 px on PC, scalable to 200% without loss of content or function.

## Not to be confused with

Not integer upscaling of pixel art (PIX-01, which enlarges the whole screen) and not animated text effects (UI-17). Here only the text is enlarged and the layout is recomputed around it. Nor is it nine-slice (UI-14) itself, though nine-slice is the usual way to let boxes grow.

## Use it for

Subtitles, dialogue boxes, tooltips (UI-12), menus, item descriptions and quest lists; especially important when supporting several languages (German runs long, Japanese has different line-break rules).

## Tunable parameters

text scale steps (100–200%) · minimum base size per platform · max box size before scrolling · line-break rules per language (kinsoku for Japanese) · icon scaling · fallback font chain

## Request prompt

Add a text-size setting to the game (100%, 150%, 200%): lay out all text measure-first — measure the text with the font's metrics, then decide box size and line breaks; let dialogue and tooltip boxes grow with their content as nine-slices, switching to scrolling when needed; scale icons together with text; fall back to a secondary font for missing glyphs. Test at 200% with the longest translated strings: no text may be clipped or overlap.

## Implementation hint

Build UI layout as measure → arrange: call the font system's measure function at the current scale, then size containers (auto-size / layout groups in most engines, or your own flex-like pass). Prefer SDF/vector fonts so 200% stays sharp; bitmap fonts need extra baked sizes. Keep a per-language line breaker and a fallback font list. Add a debug toggle that forces 200% and pseudo-localised long strings to catch overflow early.
