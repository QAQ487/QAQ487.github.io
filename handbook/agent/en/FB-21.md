# FB-21 · Audio-visual beat quantization

**Aliases:** 打擊跟著節拍; 特效對拍; 音樂同步回饋; Beat quantization; Beat-synced feedback; Music-synced VFX; Rhythm sync; ビート同期

**Group:** Combat feedback & game feel
**Subcategory:** Rhythm sync

## What you see

The player's actions still take effect immediately, but presentation — flashes, camera nudges, particle bursts — is snapped to the nearest musical beat (or a subdivision), so a whole fight feels performed to the music. Beat time must come from the audio clock rather than frame time, or it drifts within minutes; judgement and presentation can be separated, with judgement still using the real input time.

## Not to be confused with

Not the timing window of a rhythm game itself (that is gameplay) and not anticipation (ACT-09, the wind-up before an action). This entry only aligns when the presentation appears with the musical beat.

## Use it for

Music-led action games, rhythm shooters, beat-synced ambient lights and UI pulses, the musical climax of a boss fight.

## Tunable parameters

BPM from track · subdivision 1/4–1/16 · max delay 50–100 ms · beat pulse scale 2–5% · clock: audio DSP time (starting points)

## Request prompt

Add a beat-quantised presentation layer: compute the current beat position from the audio playback time (not frame time) and the track BPM; when the player lands a hit, apply damage immediately but delay the hit flash and camera nudge to the next 1/8 beat, playing them immediately if the next beat is more than 80 ms away (starting value). Also make the UI frame scale up 3% on each beat and settle back, with no brightness flashing.

## Implementation hint

beat = (audioTime - songOffset) * BPM/60; next = ceil(beat*sub)/sub; delaySec = (next-beat)*60/BPM; if delaySec <= maxDelay schedule FX at audioTime+delaySec else play now. Drive pulses with f = 1 - frac(beat) eased. Resync from the audio clock every frame; never accumulate frame dt.
