# FB-19 · Reticle bloom and spread recovery

**Aliases:** 準星會擴大; 連射越來越不準; 準心收縮; Reticle bloom; Crosshair spread; Spread recovery; Dynamic crosshair; レティクル

**Group:** Combat feedback & game feel
**Subcategory:** Aiming & handling

## What you see

While firing continuously or moving, the four ticks of the crosshair spread outward to show larger bullet spread; after the player stops firing or stands still, the reticle eases back in. Players read the size to know whether the next shot will be accurate and choose to tap-fire or spray. The reticle size should match the real spread angle, or it misleads.

## Not to be confused with

Not recoil camera kick (FB-08, where the camera itself moves) and not a hit marker (UX-03, confirming a hit). Reticle bloom describes where the next shot might land.

## Use it for

Shooter crosshairs, bow-draw aiming circles, landing-uncertainty rings for thrown items.

## Tunable parameters

spread per shot 0.3–1° · max spread 4–8° · move penalty 1–3° · recovery delay 0.05–0.15 s · recovery half-life 0.1–0.3 s (starting points)

## Request prompt

Add reticle bloom to shooting: each shot adds 0.6° of spread (starting value) up to 6°; moving adds another 2°; 0.1 s after firing stops, decay exponentially back to the base value (half-life 0.15 s, starting value). Convert the current spread angle to screen pixels for the tick distance so the drawn area equals the real cone of fire.

## Implementation hint

spread = min(max, spread + perShot) on fire; target = base + (moving? movePenalty:0); after delay: spread = target + (spread-target)*exp(-ln2*dt/halfLife). Tick offset px = tan(spread)*focalLengthPx. Fire direction samples a cone of the same angle so visuals match gameplay.
